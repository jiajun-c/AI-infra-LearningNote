# 迭代器

## 可迭代对象 vs 迭代器

|类型|要求|例子|
|---|---|---|
|可迭代对象 Iterable|实现 `__iter__`，返回一个迭代器|`list`、`dict`、`range`、生成器函数|
|迭代器 Iterator|实现 `__next__`，且 `__iter__` 返回 self|`iter([1,2])`、生成器对象|

`for x in obj` 做的事：

```text
1. 调 iter(obj) → 拿到迭代器（即 obj.__iter__()）
2. 循环调 next(it)，直到抛 StopIteration
3. StopIteration 被 for 吞掉，循环正常结束
```

所以**迭代器一定可迭代，可迭代对象不一定是迭代器**。`range` 返回的是可迭代对象，不是 list。

## 为什么迭代器的 `__iter__` 要返回 self

因为迭代器本身也是可迭代的，`for` 直接作用在迭代器上时得能工作。这也带来了迭代器的核心特性：**一次性**。迭代器耗尽后不会重置，再 `for` 一次拿到的是空的。

```python
it = iter([1, 2, 3])
list(it)    # [1, 2, 3]
list(it)    # []          ← 已经耗尽了
```

对比可迭代对象（如 list），每次 `for` 都会调 `__iter__` 拿一个**新的**迭代器，所以可以反复遍历。

## 生成器就是迭代器的语法糖

任何带 `yield` 的函数，调用时不会执行函数体，而是返回一个**生成器对象**——它自动实现了 `__iter__` / `__next__`。所以生成器天然是迭代器，省掉了手写状态机的功夫。
