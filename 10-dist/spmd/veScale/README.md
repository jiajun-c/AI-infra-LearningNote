# veScale

## 1. 背景

对于现在的大模型而言，为了将模型和并行策略之间进行解耦，采用了SPMD的编程范式，例如torch的DTensor。

但是对于torch的DTensor而言其也存在着两个问题

- 一致性问题，切分后多卡下生成的随机数和单卡下的不一致
- 性能问题：DTensor有复杂的Dispatch逻辑，导致大量的CPU侧开销


## 2. 解决方法

- 采用了一个单卡一致性的随机数生成算法
- 采用了一个高效的dispatch逻辑
- 优化了DTensor的通信

### 2.1 一致性随机数生成算法

做的第一步将局部下标映射到全局下标

然后第二步将全局下标映射到虚拟RNG状态，而不是使用其在单卡内的线程编号

### 2.2 基于规则的bypass

将更加专化的规则放在前面，把通用的规则放在后面，从而进行优化

### 2.3 缓存规则配置

如果没有完全匹配的规则，那么会去查看缓存，只在第一次跑完整的，同时相比于之前的采用了更小的hash

### 2.4 C++优化核心代码

把核心部分使用C++编写，相比与DTensor的python代码性能更好
